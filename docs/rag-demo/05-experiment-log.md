# DEMO：科研实验日志管理建议

> DEMO 知识文档：本文件是为开发检索功能编写的管理示例，不是机构官方规范、论文原文或已实施的科研制度。

## 实验可追溯信息

每次实验建议记录 Run 标识、关联任务、研究目的、输入数据版本、代码提交标识、依赖环境、主要参数、随机种子和开始结束时间。若代码尚未提交，应说明当前修改及其保存方式，不能虚构提交标识。对于 3DGS，应记录训练图像集合、测试划分、相机位姿来源、训练步数和关键渲染设置。

将“客观观察”与“原因假设”分别记录。客观观察可以包括真实错误消息、完成的训练步数、保存的截图或实际测得的指标；原因假设如“可能由于视角覆盖不足”需要后续验证。不能把模型推测的原因写成已经证实的实验结论，也不能将 DEMO 文档中的示例文字当成真实实验日志。

## 指标与产物

保存 PSNR、SSIM 等指标时记录数值、单位、评价数据范围和实现版本，并说明是训练集还是测试集。关联渲染图、模型、点云、检查点和报告等产物的路径与生成时间；记录路径本身不等于文件已存在或内容已验证。失败实验也应保留必要上下文，避免只记录成功结果而丢失排查依据。

## DEMO 日志组织示例

一条日志可包含时间、级别、事件和证据来源，例如“完成相机注册检查，具体注册列表见保存的报告”。没有实际报告时只能写“计划检查”，不能编造数量或指标。修改原始记录时保留修订原因，使参数变化和结果之间的关系可追溯。日志不应包含 API Key、数据库密码或未经授权的个人信息。

实验对比需要固定或明确说明数据、环境和参数差异。后续分析从原始记录和产物出发，必要时复现实验，再判断变化原因。本文件中的建议仅用于演示检索结果的来源追溯，不构成项目真实实验记录，也不保证任何特定科研方法有效。
